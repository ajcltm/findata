# node 할 일이 결과물을 다시 풀어 써서 생긴 문제

- 작성: 2026-11-16, 프로젝트 매니저
- 상황: N-003(src 코드 옮기기). 이 node는 승인한 재분류안(N-002 결과물)대로 코드를 옮긴다.
- 사용자의 말: "노드를 너무 세분화하니까 일이 제대로 안되잖아. 그냥 분류표대로 재분류한다. 하나로 되잖아."

## 일어난 일

1. 프로젝트 매니저가 N-003에 `do`만 썼다. 지침 규칙은 "단계가 하나면 `do`만 쓴다"다.
2. 대시보드 node 칸에 할 일이 비어 보였다. 사용자가 이유를 물었다.
3. 프로젝트 매니저가 재분류안의 표를 할 일 5줄로 다시 풀어 썼다.
4. 사용자가 물었다: "진짜 이거만 하면 분류표대로 돼?"
5. 대조해 보니 할 일 2곳이 표와 달랐다.
   - "쓰지 않는 파일 8개": 실제로는 파일 7개와 클래스 1개다.
   - 빈 폴더 삭제가 빠졌다.
6. 할 일을 고칠 때마다 N-003의 승인이 풀렸다. 사용자는 2번 다시 승인해야 했다.
7. 최종 할 일은 1줄이 되었다: "재분류안의 트리와 표대로 재분류한다".

## 원인

| 구분 | 내용 |
| --- | --- |
| 프로젝트 매니저 판단 (확인) | 이미 승인한 결과물(표)을 할 일로 다시 썼다. 사본이 생겨 원본과 어긋났다 |
| 대시보드 (확인) | node 칸은 `body`(`### 할 일`)를 보여 준다(`dashboard_data.py:301`). `do`만 있으면 할 일이 비어 보인다 |
| 지침 (확인) | `/node`는 "단계가 하나면 `do`만 쓴다"고 쓴다. 그러나 대시보드에는 할 일이 비어 보인다. 두 규칙이 맞지 않는다 |
| 승인 규칙 (확인) | 할 일 문구만 고쳐도 node 승인이 풀린다 |

## 영향

- 사용자가 할 일을 검토하는 데 시간을 썼다. 할 일은 표와 같은 내용이었다.
- 승인을 2번 더 받았다.
- 사본이 틀려서 잘못 옮길 위험이 생겼다. worker가 할 일만 따르면 표의 일부를 빠뜨린다.

## 개선안

1. `/node` 지침에 다음을 더한다: "앞 node의 승인된 결과물이 할 일을 정하면, 할 일에는 그 결과물 경로만 쓴다. 내용을 다시 풀어 쓰지 않는다."
2. 대시보드: `### 할 일`이 없으면 `do`를 할 일 자리에 보여 준다.
3. 승인 규칙: 할 일의 표현만 바뀌고 `do`, `out`, `pre`가 그대로이면 승인을 유지하는 안을 검토한다. 또는 바뀐 줄을 보여 주고 한 번에 다시 승인받게 한다.
