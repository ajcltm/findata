## 1. 자동 커밋이 사용자의 커밋하지 않은 변경까지 담는다

### 일어난 일

1. N-003 전에 사용자의 커밋하지 않은 변경이 있었다: `src/alpha/indicators/kalman.py`(공백 1칸).
2. 프로젝트 매니저가 worker에게 "이 파일을 고치지 않는다. 커밋하지 않는다"고 지시했다 (MEMO-006).
3. worker는 지시를 지켰다. `kalman.py`는 작업 전 백업과 같다(`cmp`로 확인).
4. node가 끝나자 훅이 `src/` 전체를 커밋했다. 커밋 `de85e88`에 `kalman.py`의 사용자 변경이 들어갔다.

### 원인 (확인)

- 훅이 결과물 자리(`out: src/`) 전체를 커밋한다. node가 바꾼 파일과 원래 있던 변경을 구분하지 않는다.

### 개선안

- A) node 시작 때 결과물 자리의 `git status`를 기록한다. 커밋할 때 시작 전에 바뀌어 있던 파일은 뺀다.
- B) 결과물 자리에 커밋하지 않은 변경이 있으면 node 시작 전에 사용자에게 알리고 멈춘다.
- 추천: A와 B를 함께 한다.

## 2. 자동 커밋이 `.gitignore`에 걸린 새 파일을 빠뜨린다

### 일어난 일

1. 재분류안대로 `src/alpha/config/log.py`를 `src/legacy/config_log.py`로 옮겼다.
2. `.gitignore` 169행 `**/*config*.py`가 새 이름에 걸렸다.
3. 커밋에는 옛 파일 삭제만 들어갔다. 새 파일은 디스크에만 있고 git에는 없다.

### 개선안

- 커밋 전에 "삭제된 추적 파일"과 "새로 무시된 파일"을 짝지어 찾는다. 짝이 있으면 보고한다.

## 3. `cd` 뒤 상대 경로를 프로젝트 루트 기준으로 판정한다

### 일어난 일

1. worker가 `cd src` 뒤 `mkdir alpha/core`를 실행하려 했다 (추정. 차단 로그에 명령 원문이 없다).
2. 훅이 `alpha/core`를 프로젝트 루트 기준으로 읽었다. `src/` 밖으로 판정하고 막았다.

### 개선안

- 명령 안의 `cd <경로>`를 따라가 상대 경로를 바꾼다.
- 또는 worker 지침에 "Bash 경로는 프로젝트 루트 기준으로 쓴다"를 넣는다.

## 4. 사용자에게 커밋이 자동이라는 것이 보이지 않는다

### 일어난 일

- `/run` 4절은 "통과한 node는 커밋한다 (승인 범위의 git 커밋이 자율일 때)"라고 쓴다.
- 프로젝트 매니저는 실행 전에 이 규칙을 확인하지 않았다. 그래서 "커밋하지 않는다"고 사용자에게 잘못 말했다.

### 개선안

- `/run` 2절(분배)에 "승인 범위의 커밋 규칙을 확인하고 사용자에게 알린다"를 넣는다.
- 대시보드 실행 칸에 "완료 시 자동 커밋"을 표시한다.
