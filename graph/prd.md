# 🎯 요구사항 (PRD)

> 무엇이 있어야 하는가. 요구사항 하나가 유스케이스 여러 개로 나뉜다.

---

## 🎯 REQ-001 코드 이해 설명서

- status: approved
- source: 2026-11-14

사용자가 기존 트레이딩 프로그램 코드를 하나씩 이해할 수 있어야 한다.
사용자가 지정한 스크립트 1개 또는 흐름 1개마다 설명서 1개를 받아야 한다.

### 📏 조건
- 설명서는 `out/code_docs/`에 저장한다.
- 대상 코드를 실행하지 않는다. 코드를 읽어 예시 값을 따라간다.
- 실제 증권사 API(`src/kis/`, `kis_broker.py`)를 부르지 않는다.
- 대상은 사용자가 지시할 때 정한다.

---

## 🎯 REQ-002 src 파일 재분류

- status: approved
- source: 2026-11-16

`src/`의 클래스와 함수가 성격에 맞는 파일과 폴더에 있어야 한다.
재분류한 뒤에도 프로그램은 원래와 같이 작동해야 한다.

### 📏 조건
- 기능을 바꾸지 않는다. 코드는 위치와 import만 바꾼다.
- 테스트를 만들지 않는다.
- 대상 코드를 실행하지 않는다. 실제 증권사 API(`src/kis/`, `kis_broker.py`)를 부르지 않는다.

---

## 🎯 REQ-003 칼만필터 OFI 전략

- status: approved
- source: 2026-11-17

칼만필터를 활용한 OFI 전략을 개발해야 한다.
전략은 설계 문서, indicator 코드, strategy 코드의 순서로 사이클을 되풀이하며 발전한다.

### 📏 조건
- 출발점은 레퍼런스의 자체 칼만필터 전략(`reference/081_자체 칼만필터 모델.md`)이다. 이 문서가 `v0`이다.
- 현재 indicator는 데이터 수집에 쓰는 `src/alpha/indicators/kalman.py`이다. 이 코드가 `v0`이다.
- 사이클 1개가 버전 1개다. 버전 번호는 `v1`, `v2` 순서로 붙인다.
- 한 버전의 설계 방향서, 설계서, indicator, strategy는 같은 버전 번호를 쓴다.
- 이전 버전의 결과물은 덮어쓰지 않는다.
- indicator와 strategy 코드는 지금 프로젝트의 인터페이스에 맞춘다.
- 전략 설계는 md 문서로 쓴다.
- 실제 증권사 API(`src/kis/`, `kis_broker.py`)를 부르지 않는다.
