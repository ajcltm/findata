# SimBroker 이상 체결 분석 (T-001)

- 작성일: 2026-11-18
- 대상: `src/alpha/broker/sim_broker.py`와 체결가 경로
- 범위: 분석만 한다. 코드는 고치지 않는다.

> ⚠️ 이 분석에서 실제 증권사 API(`src/kis/`, `kis_broker.py`)를 부르지 않았다. DB는 읽기 전용(`mode=ro`)으로 열었다.

## 1. 요약

- 시세와 동떨어진 체결 2건을 기록에서 찾았다. 둘 다 2026-08-27 가짜 시세(`--simul`) 실행에서 나왔다.
- 원인 1: SimBroker는 지정가 주문을 시세가 아니라 **주문가**로 체결한다. 시세보다 비싼 매수 지정가는 그 비싼 값에 체결된다.
- 원인 2: 가짜 시세(`fake_kis_websocket.py`)는 삼성전자를 70,000원 부근에서 시작한다. 실제 시세는 같은 시기 245,500원~274,000원이다. 가짜 시세 체결은 실제 시세와 3배 넘게 차이 난다.
- 실제 시세 모의(`simul_mode=False`)의 체결 601건은 시세 DB와 대조했다. 차이는 최대 0.24%(호가 1단위)이다. 이상 체결은 없다.
- 가격 0 틱과 묵은 호가는 코드 경로상 이상 체결을 낼 수 있다. 기록에서는 그런 건을 찾지 못했다.

## 2. 찾은 이상 체결

### 2.1 찾은 방법

1. `logs/alpha_sim_*.log`에서 `[SIM] 주문`과 `[SIM] 체결` 줄을 모은다. 체결은 613건이다.
2. 로그 첫머리의 `simul_mode=True|False`로 가짜 시세 실행과 실제 시세 실행을 나눈다.
3. 가짜 시세 체결은 `data/alpha_data_sim_260831.db`의 `fill`·`tick` 표로 대조한다.
4. 실제 시세 체결은 `data/kis_data*.db`의 `execution` 표로 대조한다. 체결 시각 직전 120초 안의 마지막 체결가와 1호가를 쓴다.
5. 스크립트: `out/tasks/T-001/find_outlier_fills.py`. 결과 표: `out/tasks/T-001/fills_vs_market.csv`.

### 2.2 시세와 동떨어진 체결 (가짜 시세 실행)

DB의 `dt`는 가짜 시세가 만든 시각이다. 로그 시각은 실제 벽시계 시각이다.

| 날짜 | 로그 시각 | DB 시각 | 종목 | 주문 | 체결가 | 당시 시세(체결가 / 매도1호가) | 차이 |
|---|---|---|---|---|---|---|---|
| 2026-08-27 | 07:22:16 | 09:20:52 | 005930 | 매수 지정가 1주 @100,000 | 100,000 | 79,938~80,038 / 79,938~80,038 | 약 +25% |
| 2026-08-27 | 17:17:29 | 09:24:52 | 000660 | 매수 지정가 1주 @71,000 | 71,000 | 69,112~69,312 / 69,112~69,312 | 약 +2.6% |

- 근거 로그: `logs/alpha_sim_20260827_072047.log` 590~596행, `logs/alpha_sim_20260827_171543.log` 663~665행.

- 이 값은 가짜 시세 안에서는 정상이다. 실제 시세와 나란히 보면 "말도 안 되는 가격"으로 보인다.

## 3. 실제 시세 모의 체결 대조

- 대상: `simul_mode=False` 실행의 체결 601건 (2026-08-24 09:03 ~ 2026-10-23 17:54). 모두 005930 시장가 주문이다.
- 대조 DB: `kis_data_260831.db` 412건, `kis_data.db` 189건. 601건 모두 대조했다.

| 항목 | 결과 |
|---|---|
| 직전 체결가와 체결가의 차이 최대값 | 0.24% (호가 1단위, 500원) |
| 차이가 0.5%를 넘는 건 | 0건 |
| 체결가 = 직전 틱의 반대편 1호가 (매수는 매도1호가, 매도는 매수1호가) | 597건 |
| 체결가가 직전 틱의 1호가와 1단위 다른 건 | 4건 (2026-08-24 09:09, 08-24 09:54, 08-25 13:46, 09-10 11:10) |

- 4건은 호가 전문(`H0STASP0`)으로 1호가가 바뀐 뒤 체결된 건으로 본다. 대조 스크립트는 체결 전문(`H0STCNT0`)의 1호가만 본다.
- 결론: 실제 시세 모의에서는 시세와 동떨어진 체결이 없다.
- 참고: 2026-10-22, 10-23에는 15:30 뒤(최대 17:54)에도 체결이 있다. 시세 DB에 같은 시각 체결이 있고 가격도 맞다. SimBroker는 장 운영 시간을 검사하지 않는다. 이것이 의도인지는 사용자가 정한다.

## 4. 원인

### 4.1 원인 1: 지정가 체결가가 주문가로 고정된다 (확인됨)

체결가 경로:

1. `Broker._order()`가 가격이 있으면 `OrderType.LIMIT` 주문을 만든다 (`src/alpha/broker/base.py:243-248`).
2. `SimBroker.submit()`이 주문을 받고 체결 가능 시각을 정한다 (`src/alpha/broker/sim_broker.py:136-157`).
3. `Engine.feed()`가 모든 이벤트로 `SimBroker.on_market()`을 부른다 (`src/alpha/engine/engine.py:387`).
4. `on_market()`이 `_match()`를 부른다 (`src/alpha/broker/sim_broker.py:198`).
5. `_match()`가 `_fill_price()`의 값으로 `Notice`를 만든다 (`src/alpha/broker/sim_broker.py:218-230`).
6. `_fill_price()`의 지정가 분기가 체결가를 정한다 (`src/alpha/broker/sim_broker.py:262-269`).
7. `LiveRunner._handle_notice()`가 `Notice.price`를 그대로 넘긴다 (`src/alpha/engine/live_runner.py:230-236`).
8. `on_execution_report()`가 그 값으로 포지션·현금·`Fill`을 만든다 (`src/alpha/broker/sim_broker.py:302-329`).

문제 코드 (`src/alpha/broker/sim_broker.py:262-269`):

```python
probe = ev.low_price if buy else ev.high_price
...
    hit = probe < order.price if buy else probe > order.price
return order.price if hit else None
```

- 체결 여부만 시세로 판정한다. 체결가는 항상 `order.price`이다.
- 매수 지정가가 매도1호가보다 높으면 실제 거래소는 매도1호가 부근에서 체결한다. SimBroker는 지정가 전액으로 체결한다.
- 매도 지정가가 매수1호가보다 낮아도 같다. 낮은 지정가로 체결된다.
- 주석(`sim_broker.py:244-251`)은 대기 지정가만 생각했다. 즉시 체결되는 지정가(시장성 지정가)는 다루지 않는다.

재현 조건:

1. 매수 지정가를 시세보다 높게 낸다. 또는 매도 지정가를 시세보다 낮게 낸다.
2. 지연(`latency_ms`, 기본 200ms) 뒤에 체결 틱이나 봉이 하나 온다.
3. 그 이벤트에서 체결가가 지정가로 기록된다.

재현 결과 (`out/tasks/T-001/repro_limit_fill.py`, 시세 80,000원, 매도1호가 80,000원):

| 경우 | 주문 | 체결가 |
|---|---|---|
| A | 매수 지정가 100,000 | 100,000 |
| B | 매수 시장가 (비교) | 80,000 |
| C | 매도 지정가 50,000 | 50,000 |

### 4.2 원인 2: 가짜 시세의 가격 스케일이 실제와 다르다 (확인됨)

- `FakeKISWebSocket`이 모든 종목의 시작가를 `70000 + randint(-3000, 3000)`으로 정한다 (`src/kis/fake_kis_websocket.py:95-96`).
- 실제 삼성전자 시세는 같은 시기 245,500원~274,000원이다 (실제 시세 모의 체결 기준).
- 시작가가 호가단위에 맞지 않는다 (예: 70,938, 66,912). 랜덤워크는 100원 단위로만 움직여 끝자리가 그대로 남는다 (`fake_kis_websocket.py:207-213`).
- 시장가 체결가는 `round_to_tick(ask)`이다 (`sim_broker.py:256-260`). 매도1호가 74,138원이 74,100원으로 반올림되어 호가보다 싸게 산다.
- 가짜 시각은 `09:00:00 + 경과초`이다 (`fake_kis_websocket.py:215-235`). 아침 07:22에 돌려도 DB에는 09:20으로 남는다. 그래서 DB만 보면 정규장 체결로 보인다.

재현 조건: `python -m alpha sim --simul`로 실행하고 주문을 낸다.

## 5. 고치는 안

### 안 1: 지정가 체결가를 시세로 제한한다 (원인 1)

- 매수: `체결가 = min(지정가, 매도1호가)`로 한다. 호가가 없으면 `min(지정가, 체결가)`로 한다.
- 매도: `체결가 = max(지정가, 매수1호가)`로 한다. 호가가 없으면 `max(지정가, 체결가)`로 한다.
- 고칠 곳: `sim_broker.py:262-269` 한 곳.
- 주의: 대기 지정가(시세보다 유리한 지정가)는 지금처럼 지정가로 체결된다. 기존 성과는 바뀌지 않는다.
- 시험: `repro_limit_fill.py` 경우 A는 80,000, 경우 C는 79,900이 나와야 한다.

### 안 2: 시세 값을 경계에서 걸러 낸다 (원인 2와 잠재 원인)

1. `normalize.from_execution()`이 가격 0 이하 체결을 이벤트로 만들지 않는다. 또는 `Tick.trade_price`가 0 이하이면 `None`을 돌려준다.
2. `SimBroker._fill_price()`가 `probe <= 0`이면 체결하지 않는다.
3. `SimBroker`가 호가에 수신 시각을 같이 저장한다. 정한 시간(예: 5초)보다 오래된 호가로는 시장가를 체결하지 않는다.
4. 가짜 시세는 시작가를 종목별로 받는다. 시작가를 호가단위에 맞춘다.
5. 가짜 시세 체결은 `mock_simul.db`에만 남긴다. 보고 화면과 분석에서 가짜 시세 결과를 실제 시세 결과와 섞지 않는다.

## 6. 확인하지 못한 것

- `kis_data.db`(4.2GB)의 가격 0 이하 전수 확인. 사용자가 돌려 보는 방법: `sqlite3 "file:data/kis_data.db?mode=ro"`에서 `select count(*) from execution where cast(current_price as real) <= 0;`을 실행한다.
- `mock_data.db` 본체가 없다. `-shm`, `-wal` 파일만 있다. 2026-10-25 이후 실제 시세 모의의 `fill` 표는 대조하지 못했다.
- 로그에 남지 않은 체결(로그 파일이 지워진 실행)은 대조하지 못했다.
